# Highlights 4/4: selection popover editing in Live Preview

## Parent

#38

## What to build

The user-facing gesture: in Live Preview on desktop, selecting text inside a rendered passage pops a small popover of five slot swatches plus an eraser; choosing one applies the stroke through the stroke engine and writes the rewritten reference token back to the note via the editor. The first highlight pins the translation token.

- Popover gating: only when the passage is served in its requested translation — never on fallback-served, loading, or unavailable passages; never in Reading mode, embeds, or on mobile (those render read-only); only when the selection intersects the passage's verse text (chip, verse numbers, attribution excluded; selection clamped).
- Swatches show the current slot colors (CSS variables); eraser is the sixth position.
- After applying, the selection clears and the updated highlights render immediately.
- Editor suggest never offers cue tokens.

## Acceptance criteria

- [ ] Select-then-swatch paints; select-then-eraser erases; both rewrite the token minimal-diff in the file
- [ ] First highlight inserts the explicit translation token
- [ ] No popover on fallback/loading/unavailable passages, Reading mode, embeds, or mobile
- [ ] Selection straying outside the passage clamps; wholly-outside selections show no popover
- [ ] Feature-level tests stub the editor/plugin per the existing rendering feature spec pattern
