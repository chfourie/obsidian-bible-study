# Highlights 1/4: render hand-typed highlight cues

## Parent

#38

## What to build

Hand-typed Highlight Cues render. Typing `{John 15:1-16 nkjv block h1/5.4-5.25 h2/7.0-9.12}` shows the tinted spans over the passage text in Reading mode and Live Preview, for both `inline` and `block` display, using a shipped default palette.

- Reference core parses cue tokens alongside translation/display tokens: canonical form `h<slot>/<verse>.<start>-<verse>.<end>`, shorthand (`h1/5.4-25`), chapter-qualified form for cross-chapter references (`16:2.10`). Offsets are end-exclusive chars into the stored verse text.
- Malformed cues, unknown slots, and cues addressing verses outside the reference follow the existing invalid-token rule: highlighted in source, ignored, reference renders normally. Cues in annotation frontmatter `ref` values are inert.
- Rendering weaves highlight spans into verse segments: background tint only, text color preserved (red-letter stays red). Offsets past the verse's text length clamp; spans over translation content gaps render nothing; cue spans crossing reference gaps render only the verses the reference contains.
- Fallback-served passages render no highlights. Chip-only references carry cues but render nothing. Reader pane renders no highlights.
- Default palette (muted yellow, green, blue, pink, orange; translucent dark variants) shipped as CSS variables `--ss-hl-1`…`--ss-hl-5` scoped by `.theme-light`/`.theme-dark`.

## Acceptance criteria

- [ ] Canonical, shorthand, and chapter-qualified cues parse; parser tests cover invalid/duplicate/out-of-reference cues landing in invalid tokens
- [ ] Highlights render in Reading mode and Live Preview, inline and block, with red-letter coexistence
- [ ] Clamping, gap, and content-gap behavior verified at the passage-view seam
- [ ] Fallback substitution suppresses highlights
- [ ] Light and dark palette variants apply via CSS variables
